# UC-M8-22 — Confirm Batch Payment (`ConfirmBatchPaymentUseCase`)

**Module:** M8 — Financeiro ([module spec](../m8-financeiro.md))
**Context package:** `br.gravita.finance`
**Roadmap phase:** Phase 5 — Financeiro (doc §14)

## Functional requirement

§9.2 Contas a Pagar — "Pagamento em lote: seleção múltipla de títulos; geração de remessa CNAB para o banco." The doc doesn't separately name the confirmation step, but a remittance (`remessa`) is only half of a CNAB round trip — the bank's `retorno` file is what actually confirms a payment was executed. Added after the initial split noted the payable side had no use case symmetrical to the receivables' [`ImportBankReturnUseCase`](uc-05-import-bank-return.md) (uc-05).

## Description

Scheduled/daily job that imports a CNAB 240/400 return file confirming execution of a payment remittance generated by [`BatchPayUseCase`](uc-13-batch-pay.md) or a `PayViaPixUseCase` transfer. Matches each line to the corresponding `Payable` and creates a `Settlement` (`method = AUTOMATIC_CNAB`), moving the payable to `PAID`.

## Port signature

```java
public interface ConfirmBatchPaymentUseCase {
    BankReturnImportResult execute(ConfirmBatchPaymentCommand command);
}
```

`ConfirmBatchPaymentCommand`: `bankIntegration`, `fileContent` (CNAB 240/400 payload). Returns a `BankReturnImportResult` (confirmed/settled count, unmatched lines) — same result shape as uc-05.

## Outbound ports required

- `BankIntegrationPort`
- `PayableRepositoryPort`
- `SettlementRepositoryPort`

## REST endpoint

None — runs as a scheduled job via `BankIntegrationPort`, same pattern as `ImportBankReturnUseCase` (uc-05).

## Domain entities touched

- `Payable` (mutated: `status → PAID`)
- `Settlement` (created)

## Acceptance criteria

- [ ] Every matched, confirmed line in the CNAB return produces a `Settlement` with `method = AUTOMATIC_CNAB`, linked to the `Payable`.
- [ ] The matched `Payable`'s `status` moves to `PAID`.
- [ ] Unmatched lines are reported, not silently dropped.
- [ ] A remittance line that the bank rejects does not mark the payable `PAID` — it stays `APPROVED`, and the rejection is surfaced in the result.
